# Decision log

| # | Decision | Reason | Trade-off |
|---|---|---|---|
| 1 | One zone, ย.9; the zone is detected, not declared | The brief asks for one zone done properly. *Superseded in the second audit:* the zone was first user-declared (UNVERIFIED for every plot); it is now read from the bundled BMA GIS layer (#16, #17). | Plots in other zones get FAIL with the detected zone; ย.9 rules are not re-targeted to other zones. |
| 2 | Three building-class envelopes, best legal one wins | MR 33 applies to the *whole* building at ≥ 23 m or ≥ 10,000 m² (6 m setbacks at all levels, road eligibility, 30 % plot open space). Low-rise has different setbacks (MR 55 Cl. 50 at 2 or 3 m). Mixing classes per floor is illegal. | About 3× compute; hence the Web Worker. |
| 3 | Distance setbacks via edge capsules | Exact for concave plots. The legal test is distance to the boundary; a half-plane per edge deletes arms of L-shapes. | Reflex corners get rounded notches (legally correct). Arcs are slightly conservative (≤ 0.04 m² on the test L-shape). |
| 4 | Keep the largest piece when setbacks split a plot | One building mass per design keeps the concept clear. | The discarded area is reported, not silently dropped. |
| 5 | Plot edge = road boundary; widths are estimated, user-overridable inputs | OSM has centrelines, not legal reserves. Clause 41 and 44 distances are measured from the road boundary or centreline. *Second audit:* frontages and widths are now pre-filled from the map (#18, #19); a typed value always wins. | The result is only as good as the widths; estimated ones are badged EST. INPUT. |
| 6 | Walls with openings on all sides | Condos have windows everywhere; Cl. 50 then applies to every boundary. | Blank party walls (which allow 0.5 m or 0 m) are not explored. |
| 7 | Height = roof deck of top storey | MR 33 Cl. 1 measures to the roof deck. | Parapets and rooftop plant are not modelled. Cl. 44 measures to the highest part, so add about 1–2 m of margin in design. |
| 8 | Design B = footprint ≤ 60 % of A | A clear, deterministic open-space objective that applies to every plot and type. On high-rise sites, B recovers the floor area with height. | On low-rise sites B loses floor area; this is shown, not hidden. |
| 9 | EIA is INFO, not a design driver | An EIA is a permitting step, not a buildability limit. The 4,000 m² usable-area trigger catches nearly every FAR-7 condo anyway. | The unit and usable-area figures are labelled estimates. |
| 10 | UNVERIFIED ≠ PASS | Missing evidence must stay visible. *Second audit:* the zone, the Bangkok ordinance and the permeable area are now evaluated, so UNVERIFIED remains only where evidence is actually missing: a plot within 10 m of a zone boundary, outside every zone polygon or without zone data, unknown road continuity, no road edge selected, or a user-declared station. | A typical in-zone plot with known access widths shows no UNVERIFIED items; checks based on map estimates are badged instead. |
| 11 | Engine in a Web Worker | 50–220 ms per evaluation would stutter map interaction on every input. | Results arrive about 1 frame to 300 ms later; a pulse marks recalculation. |
| 12 | SVG overlay for drawing and drag | GeoJSON updates are queued through MapLibre's tiler (measured 450–1,100 ms under load). | A second rendering path for transient feedback only. |
| 13 | `querySourceFeatures` for hiding context buildings | `queryRenderedFeatures` cannot see hidden features, which created an idle render loop. | Source features are per tile; duplicate ids are harmless. |
| 14 | `safeClip` retries | polygon-clipping 0.15 has known failures on near-coincident vertices. | Snaps and perturbations are ≤ 10 µm, far below planning precision. |
| 15 | Same `runFeasibility` in browser, worker and API | One authoritative engine; the API test asserts identical output. | — |
| 16 | Bundle the BMA zoning layer as static GeoJSON, validated against the Gazette | The official ArcGIS service is geo-blocked from outside Thailand and from Cloudflare's edge, so a runtime dependency would fail. The plan map is part of a regulation (Copyright Act s.7). All 20 checkable zone counts match the Gazette. | Data is a snapshot; refresh with `scripts/ingest/bma-zoning.mjs` (needs Thai network / GitHub Actions). |
| 17 | Zone PASS only when 100 % in ย.9 and ≥ 10 m from a boundary | GIS boundaries are indicative at metre precision; the annexed map is binding. | Plots near boundaries stay UNVERIFIED. |
| 18 | Map-derived road widths are always "EST." | OSM has centrelines, not legal reserves; no cadastral source is open. | Users must enter surveyed widths to clear the flag. |
| 19 | Estimate road widths in the browser from the already-loaded vector tiles | No extra service, no rate limits; same data the user sees. z14 tiles drop many small buildings, so facade clearance is often missing (confidence "low"). | Estimates are coarse. |
| 20 | Parking counts in FAR; large-building rate applied literally | Plan Cl. 54 exempts only extra public parking from FAR; "พื้นที่อาคาร" includes parking floors. | Conservative; may overstate parking versus a practitioner reading that excludes parking floors. |
| 21 | Storeys = footprint ∩ own allowable polygon ∩ storey below | Guarantees containment and nesting even when a plane splits the plot. | One or two extra polygon intersections per clipped storey. |
| 22 | Class pruning + secant searches + caches | Meets the < 100 ms target (measured 13–30 ms) without weakening any rule. | More code paths; covered by the invariant tests. |
